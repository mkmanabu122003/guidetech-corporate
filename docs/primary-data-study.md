# 一次データ記事の作り方

作成: 2026-08-10

レビューで「AIに引用される理由がない」「被リンク獲得の手段がない」と指摘した2点は、
**同じ1本の記事で同時に解決できます。** それが一次データ記事です。

公開情報を正確に整理した記事は、他社も同じものを作れます。
**実際にやってみた結果の数字は、他所に存在しません。** AI検索も被リンクも、そこに集まります。

しかもこの調査は、GuideTech の本業そのものです。受注前の営業活動としてやっても損がありません。

---

## なぜこれが最優先なのか

| 施策 | 被リンク | AI引用 | 商談化 | 追加コスト |
|---|---|---|---|---|
| 記事をあと10本書く | ほぼ効かない | 弱い | 中 | 大 |
| 被リンク営業だけする | 効く | 弱い | 小 | 中 |
| **一次データ記事1本** | **強い** | **強い** | **強い** | **中（実務と兼用可）** |

一次データ記事は「取材に応じてくれた業者」というリスト自体が、そのまま営業資産になります。

---

## 推奨テーマ（実行順）

### 1本目: 抹茶卸への一斉問い合わせ調査

検索需要が最大で、かつ「返信が来ない」「輸出できない」という記事の主張を
**自分の実測で裏付けられる**テーマです。

**手順**

1. 対象を50社集める。産地別（宇治・西尾・鹿児島・静岡・八女）に分散させる。
   出典は業界団体名簿、展示会出展社リスト、各社サイト。
2. 同一の日本語問い合わせ文を送る。内容は固定：
   - 海外バイヤーである旨
   - 想定数量（例：まず10kg、年間100kg規模）
   - 輸出対応の可否
   - 最小ロットと価格帯
   - 残留農薬・産地証明の発行可否
3. 送信日、返信日、返信内容を記録する。**返信がないことも데이터です。**
4. 2週間後に1回だけ丁寧に再送し、それも記録する。

**記録する項目**

| 項目 | 理由 |
|---|---|
| 送信数 / 返信数 / 返信率 | 記事の中心的な数字 |
| 初回返信までの日数（中央値） | 「日本は遅い」を定量化 |
| 輸出対応可の社数 | 「entity wall」の実証 |
| 最小ロットの分布 | 他所にない実用情報 |
| 価格帯の分布 | 同上。レンジで示し、社名は伏せる |
| 証明書の発行可否 | 記事の検証パートを裏付ける |
| 英語で返信した社数 | 「日本語が必要」の実証 |

**公開時の注意**

- **社名は出さない。** 許諾なく問い合わせ内容を公開すると信頼を失い、今後の取引にも響きます。
  「50社中12社が返信」という集計値のみを出す。
- 調査手法（対象の選び方、送信文、期間）を明記する。**手法が書かれていない数字は引用されません。**
- 調査日を明記し、再調査したら更新する。

### 2本目以降の候補

- 同じ手法をトレカ卸、化粧品OEM、包丁メーカーに横展開する
- 日本の展示会に代理出展し、ブースでの反応を記録する
- 検証レポートを10件納品した時点で「10社検証して分かった赤信号の傾向」

## 記事化の型

```
1. 何を調べたか（1段落で数字を先に出す）
2. 手法（対象・送信文・期間・除外条件）
3. 結果（表とグラフ。数字が主役）
4. 数字から言えること（3〜5項目）
5. 数字から言えないこと ← ここを書くと引用されやすくなる
6. 再現方法（読者が自分でやれるように）
7. CTA
```

5番目が効きます。限界を明示した調査は、AI にとっても人間にとっても信頼できる情報源です。

---

## 公開後にやること

1. 調査対象にした業界団体・メディアに「こういう調査を公開した」と1通送る（売り込みではなく共有）
2. `r/importexport`、TCG や食品輸入のコミュニティで、**関連する質問に回答する形で**引用する
3. JETRO や商工会議所の海外バイヤー向けリソースへの掲載を打診する
4. Search Console で被リンクの発生を追う

## 実装側の準備

記事の書式は `scripts/generate-sourcing-articles.mjs` の既存記事と同じ構造で足ります。
表は `["table", { head: [...], rows: [...] }]` ブロックが使えます。

構造化データについては、調査記事には `Dataset` スキーマの併記を推奨します。
AI が「これは一次データである」と認識しやすくなります。実装は調査結果が出てからで十分です。
